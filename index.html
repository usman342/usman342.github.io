Profile

About

I have spent more than 11 years on the parts of software that have to keep working: backend applications, Linux servers, and the operational detail around them. That includes PHP systems and REST APIs, MySQL and MariaDB, and infrastructure on AlmaLinux and CentOS with Apache, Nginx, and Squid.

Production reliability is the through-line. I want to know how a service is configured, what to look at when it degrades, and which steps should be automated so they do not depend on memory. Where workloads belong in virtual machines, I use Proxmox, and I treat backups as part of the design.

Leadership, for me, is technical. I plan the work, review the code, and mentor engineers who are taking on harder problems. The aim is a team that can ship, explain its choices, and recover when production does something unexpected.

Practice areas

Practice area

Proxy infrastructure and reliability

Problem
Proxy traffic has to keep moving when configuration, capacity, or an upstream changes.
Approach
Run it on Linux with Squid, and with Apache or Nginx beside it, and treat diagnosis as part of the design rather than an afterthought.
Technologies
Squid, AlmaLinux, CentOS, Apache, Nginx
Outcome
A proxy path that can be configured and diagnosed in production.

Practice area

Proxmox cluster management

Problem
Services need isolation, a place to restore from, and a way to manage hosts that is not a pile of one-off machines.
Approach
Run workloads as virtual machines on Proxmox VE, with Proxmox Backup Server for backups.
Technologies
Proxmox VE, Proxmox Backup Server
Outcome
Virtual machines that are provisioned, maintained, and restorable as part of normal operations.

Practice area

Checkout and fraud prevention

Problem
Taking payment is not finished when a charge succeeds. Failed payments and abuse belong in the same flow.
Approach
Checkout with Stripe, PayPal, cryptocurrency, and other payment methods, with fraud prevention treated as part of the payment design.
Technologies
Stripe, PayPal, cryptocurrency, PHP, REST APIs
Outcome
Checkout flows built around successful payment and resistance to abuse.

Practice area

Linux server migrations

Problem
Aging servers and OS releases make every later change riskier.
Approach
Plan the move onto maintained Linux, including AlmaLinux and CentOS, and check that the new host matches the behavior that mattered on the old one.
Technologies
AlmaLinux, CentOS, Apache, Nginx, Virtualmin, cPanel, Linux
Outcome
Migrations handled as operational work: what moves, what is verified, and what is turned off.

Practice area

Monitoring and incident response

Problem
A production fault discovered only by a user report is already late, and the fix should not live only in someone's memory.
Approach
Monitoring and hands-on troubleshooting, plus automation in Python, Node.js, Bash, and shell. CI/CD where it removes a repeated manual path.
Technologies
Python, Node.js, Bash, shell scripting, CI/CD
Outcome
Issues that are easier to see, and repeat work that depends less on manual steps.

Approach
